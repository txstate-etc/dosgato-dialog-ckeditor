A Svelte form control (`@dosgato/dialog-ckeditor`) that wraps CKEditor 5 for the DosGato CMS, compatible with `@dosgato/dialog` (its Chooser provides the asset/link browsing modals). The real host is dosgato-txstate-admin (../dosgato-txstate/admin) — dosgato-admin itself does not depend on this package.

The editor (CKEditor 48) is built **in this repo** as plain ESM against the single `ckeditor5` package: stock plugins plus four custom ones (the two browse hooks, the class-based table properties and a trimmed cell properties UI (background and text alignment)). It was upgraded from 35.4 in 2.0.0; [PLAN.md](PLAN.md) is the record of that upgrade and holds the CKEditor 48 gotchas and the reasoning behind non-obvious content-conversion choices — read the relevant chunk notes before changing editor config, plugins, or storage conversion. The old prebuilt bundle (`@dosgato/ckeditor`, ../dosgato-ckeditor) is frozen at 1.2.x for carbon-svelte-ckeditor and is not part of this package anymore.

User-facing changes go in [CHANGELOG.md](CHANGELOG.md); content rewrites on re-save are worth calling out there. Known follow-up work is in [ISSUES.md](ISSUES.md). There is no CI; the maintainer publishes by hand.

## Layout

- [src/lib/editor.ts](src/lib/editor.ts) — the editor build: stock plugin list, default config, `licenseKey: 'GPL'`, CSS imports. Dynamically imported so it stays code-split. See PLAN.md chunk 3 notes for the tableProperties `defaultProperties` gotcha. `strictRemovePlugins` maps toolbar items to plugins for the `strictHtml` prop, so a new builtin plugin needs an entry there (or in `alwaysLoaded`) or strict editors won't load it. Its `translations` dictionary relabels Bookmark as "Anchor"; re-check it against upstream strings on CKEditor upgrades.
- [src/lib/assetbrowser.ts](src/lib/assetbrowser.ts) — the AssetBrowser plugin (plugs `browseImage` into the stock image insert UI via `ImageInsertUI.registerIntegration`) and the `EditorConfig.assetBrowser` type augmentation (public contract with hosts).
- [src/lib/linkbrowser.ts](src/lib/linkbrowser.ts) — adds the `browseLink` browse button to the stock link form (LinkUI has no sanctioned hook for a modal browser, so it decorates the lazily-created form view).
- [src/lib/tableproperties.ts](src/lib/tableproperties.ts) + [src/lib/tablepropertiesview.ts](src/lib/tablepropertiesview.ts) — DosGato's class-based table properties (width/border/alternate-row/header-color classes on `figure.table`, plus stock's class-based `tableAlignment`; header rows/columns are left to the stock row/column dropdowns), registered as the `tableProperties` toolbar component in place of stock TablePropertiesUI (stock TablePropertiesEditing stays for inline-style round-trip). Also round-trips the legacy `border` attribute and keeps it and `cellpadding` away from the stock converters, which would turn them into inline styles that override theme CSS. See PLAN.md chunk 5 notes for the 48 gotchas (scopedHeaders post-fixer, `_`-prefixed internals, shared balloon). [src/lib/editor.css](src/lib/editor.css) previews the classes in the editing view, after dosgato-txstate's `richEditorTable` mixin.
- [src/lib/tablecellproperties.ts](src/lib/tablecellproperties.ts) — stock TableCellPropertiesUI trimmed (by CSS class) to background color and text alignment; stock TableCellPropertiesEditing stays for round-trip.
- [src/lib/RichTextEditor.svelte](src/lib/RichTextEditor.svelte) — creates the editor (dynamic `import('./editor.js')`), wires the `assetBrowser` config callbacks (`browseImage`, `browseLink`) to Chooser modals, syncs editor data with the svelte-forms store.
- [src/lib/FieldRichText.svelte](src/lib/FieldRichText.svelte) — the form-field wrapper. Its `initialize()` is everything that runs between CMS storage and the editor: resolving DosGato's JSON link descriptors (`href='{"type":"url|page|asset",...}'`) to real hrefs, plus CKEditor4→5 image markup conversion. The DOM transform lives in [src/lib/storage.ts](src/lib/storage.ts) so the round-trip tests run the identical code. Content preservation across this boundary is the core requirement of the upgrade — see PLAN.md chunk 1.
- [src/lib/RichTextTypes.ts](src/lib/RichTextTypes.ts) — preset editor configs. Toolbar names all resolve to stock/current plugins; the `table.tableProperties` custom keys (header colors, width classes) feed tableproperties.ts and coexist with stock keys like `defaultProperties`.

## Commands

- `./test.sh` (also `npm test`) — vitest browser mode (installed Chrome via playwright). [test/roundtrip.test.ts](test/roundtrip.test.ts) runs each `test/samples/NNN.html` (anonymized production content in stored form, JSON link descriptors and all) through `resolveStoredHtml` with mock descriptor resolution and the real editor, and compares `getData()` to `test/expected/NNN.html` (file snapshots; a newline is added after block closing tags for readable diffs, see `formatOutput` in [test/roundtrip.ts](test/roundtrip.ts)). Run it after any change touching content conversion. `./test.sh -u` accepts intended changes — review the `test/expected` diff and the /report page before doing that, and call out content rewrites in CHANGELOG.md. Sample numbers match the ones in PLAN.md (they were 35.4-baseline indexes); the 35.4 baseline itself is retired.
- `npm run import-samples` — [test/import.test.ts](test/import.test.ts) anonymizes a gitignored `richexamples.json` of real content into `test/samples` ([test/anonymize.ts](test/anonymize.ts): words → same-length lorem, digits scrambled, alt/title/mailto/tel too, `data:` images → 1px placeholders). It proves each anonymized sample is equivalent by masking letters/digits in both editor outputs and requiring them identical. Never commit un-anonymized content; the repo is public.
- `npm run dev` — vite dev server with a demo page.
- `/report` on the dev server — viewer for the last test run (`test/last-report.json` holds the actual output of failing samples): expected vs current rendered side by side (optionally with the stored input), or a folded source diff. Renders with the txst theme's real content CSS by default, compiled on request from `../dosgato-txstate` (`src/routes/report/livecss`); a toggle switches to CKEditor's content CSS, which dosgato-txstate doesn't use.
- `npm run package` / `prepublishOnly` — `svelte-package` to `dist/`; no bundling happens here, the consuming app's vite bundles everything (which is why plain-ESM editor code needs no build step).
- `npm run check`, `npm run lint`.
