# PLAN.md — CKEditor upgrade plan

Modernization plan for DosGato's rich text editing, decided 2026-08. Work the chunks in order; each is a separate session-sized unit. Update the Status lines as work lands.

This plan started life in ../dosgato-ckeditor and moved here when chunk 2 settled: the upgraded editor gets written **in this repo**, and dosgato-ckeditor is frozen. Chunks 1–2 happened there; their artifacts move here in chunk 3.

## Strategy decision (settled — do not relitigate)

Upgrade CKEditor 35.4 → latest (48.x as of Aug 2026) in **one jump**, not version phases. Reasons:

- v42 replaced the entire installation model ("new installation methods": single `ckeditor5` package, bundler-agnostic, separate CSS). The old setup — individual `@ckeditor/ckeditor5-*` packages, webpack + `ckeditor5-dev-utils`, deep `src/` imports — is the deprecated "custom builds" method, unsupported since end of 2025. Intermediate stops (38, 41) would port the forks multiple times onto an already-dead platform.
- The forked plugins in ../dosgato-ckeditor/src will not migrate; they get rewritten against current APIs using the old code as the spec. Old code stays available for reference until the end.
- v37 rewrote CKEditor in TypeScript; v44+ requires `licenseKey: 'GPL'` (free for GPL use, which we are).

## Chunk 1: Content round-trip harness

**Done before touching any dependency.** Content preservation is the core requirement and the only real risk.

- Sample corpus: `richexamples.json` (`{samples: [{html}]}`, 112 real production samples, collected 2026-08). Coverage: tables incl. `full-width`/`header-color-*` classes, Word paste artifacts (`mso-`, `<w:>`, `BCX*`/`SCXW*` classes), inline styles, `<font>`/`<center>`, `<style>`/`<script>` in content, `<pre>` (samples 108–109), `p.large-text` (110–111).
- Anchor coverage (samples 100–107): empty `<a id="x" name="x"></a>` targets standalone and adjacent to headings, TOC pages with same-page `#fragment` links pointing at their own anchors (100, 103, 107), `#top` back-links (104–106), and — the tricky case — `name`-only anchors **wrapping** heading text in 107. Upstream Bookmarks models bookmarks as empty anchors; check its non-empty-anchor conversion config against the wrapping case. Any output shape is acceptable as long as the fragment value still resolves (see acceptance rule below).
- Corpus hrefs are JSON-encoded DosGato link descriptors (`href='{"type":"url|page|asset","url":...}'`). This is intentional CMS storage format; this repo's `initialize()` in `src/lib/FieldRichText.svelte` resolves them to real hrefs before content reaches CKEditor. The harness preprocessing replicates `initialize()` — once the harness lives here (chunk 3), it should call the real thing instead: (1) resolve JSON descriptors on any `[href]`/`[src]` element — for `type: 'url'` substitute the descriptor's own `url` value, for checksum/page/asset descriptors use deterministic mock paths; (2) the CKEditor4→5 image conversion.
- Anchors in production are destination targets for cross-page deep links (`<a name=...>`, some `id`+`name`), not paired with in-document `#fragment` links (corpus has ~0 deliberate ones). What must survive is the target element and its name/id value.
- Harness: load each sample into the editor, call `getData()`, diff against input, normalizing insignificant whitespace/attribute-order differences.
- **Acceptance is behavioral, not byte-for-byte.** Markup rewrites that work the same are fine — e.g. `<a name='blah'><h2>title</h2></a>` → `<h2 id="blah">title</h2>` still resolves the fragment target. Where possible, automate semantic checks instead of string equality: the set of fragment-targetable values (`id`/`name`) is preserved, link hrefs unchanged, meaningful classes/styles retained. String diffs that pass semantic checks go to human review only when novel.
- Baseline recorded against the current 35.4 build — 35.4 already mutates some content; we only care about regressions relative to that baseline, not perfection.
- Status: **done** (2026-08). Artifacts currently in ../dosgato-ckeditor: `test/harness.mjs` (playwright-core driving installed Chrome; `--record`/compare modes, details land in `test/last-report.json`), `richexamples.json`, baseline in `test/baseline-35.4.json` (raw `getData()` outputs only; normalization/profiles recomputed at compare time, so harness improvements don't invalidate baselines). Chunk 3 relocates all of it here. Baseline facts worth knowing:
  - 60/112 samples round-trip 35.4 byte-clean (after normalization); 52 mutate, 31 of those with semantic loss vs preprocessed input — all pre-existing behavior, informational only.
  - **35.4 already destroys `name`-only anchors that wrap text** (samples 74, 107): output has zero `name`/`id` attrs left, while `#fragment` links survive, so those TOC pages break if re-saved today. Empty anchors (samples 100–106) survive via the custom Anchor plugin. Chunk 4's Bookmarks work only has to beat the baseline, i.e. not regress samples 100–106; fixing 74/107 would be a bonus.
  - The editor drops some of what `initialize()` adds: `image`/`image_resized` classes and percentage widths on some images (64, 65, 82, 85), and the figure wrapper that `initialize()` mistakenly puts around non-img `[src]` elements like `<script src>` (85 — its `querySelectorAll('[src]')` isn't img-specific). It also drops the `caption` class from figures (66–70, 83) and GHS's strict style list drops various inline styles (Word junk, `display:inline-block`, some font-families).

## Chunk 2: Packaging decision

- Status: **done** (2026-08). Decision: **(b), merged into this repo.** The 48.x editor is written here as plain ESM — custom plugins + config in `src/lib`, importing the single `ckeditor5` package directly as a regular dependency. Reasoning and consequences:
  - v42+'s installation method needs no bundler config at all (icons inlined, CSS a plain importable file), so a separate prebuilt-bundle repo no longer earns its keep. `svelte-package` ships the plugin/config files as-is; the end app's vite bundles `ckeditor5` like any dependency. The `await import(...)` in `RichTextEditor.svelte` stays dynamic, so the editor still code-splits; `ckeditor5/ckeditor5.css` gets imported inside that lazy module.
  - `@dosgato/ckeditor` stays published, **frozen at 1.2.x**, for `@txstate-mws/carbon-svelte-ckeditor` (which feeds carbon-svelte's FieldRichText and apps like outcomes-assessment/ui). That package is deprecated in favor of carbon-svelte-tiptap and never joins this upgrade. Consequence: those apps ship CKEditor 35.4 until their tiptap swap lands — a pre-existing condition, but the tiptap migration inherits the deadline.
  - The dosgato-ckeditor repo is read-only reference for the fork rewrites (chunks 4–5). GitHub-archive it in chunk 6. Its `devck` copy-hack dev loop dies in chunk 3, as do this repo's `@ckeditor/*@41.x` type-only devDependencies (types come from `ckeditor5` proper).
  - Consumer map, so nobody re-derives it: this repo → dosgato-txstate-admin (the actual host — dosgato-admin itself does not depend on this package). `@dosgato/ckeditor@1.2.x` → carbon-svelte-ckeditor → carbon-svelte, outcomes-assessment/ui (frozen/deprecated path).

## Chunk 4: Shrink the fork surface (audit, then delete)

For each fork in ../dosgato-ckeditor/src, first check whether upstream 48.x now covers it; deleting beats porting.

- `Anchor/` → upstream **Bookmarks** feature (added v44). Production anchors are cross-page deep-link targets (see chunk 1 corpus facts); Bookmarks emits `<a id=...>`, ours are `name` (sometimes + `id`). A `name`→`id` upcast is acceptable — browsers honor `id` as a fragment target — as long as the value survives. Verify via harness.
- `Link/` — upstream link UI was substantially revamped (~v45); the old subclassing approach is dead regardless. Goal: reduce to just the browse-button hook (`config.assetBrowser.browseLink(currentUrl, cb)`) on the current link form, plus the click-navigation-prevention behavior. Check whether current LinkUI has sanctioned extension points before subclassing again. (JSON link descriptors are resolved by `initialize()` before reaching the editor — see chunk 1.)
- `Image/ImageTextAlternative*` — check whether stock alt-text UI now suffices.
- Also re-audit stock config coverage for anything else forked (CustomTableToolbar, list properties).

## Chunk 5: Port what's genuinely ours

- `Table/` + `Tablecellproperties/` + `Table/Commands/`: class-based semantic table properties (width, headers, header colors as CSS classes, not inline styles). Upstream still uses inline styles, so this stays custom. Biggest single piece; rewrite against 48.x table APIs using the old code as spec. Existing content with these classes must round-trip (harness).
- Whatever chunk 4 concluded must be ported rather than deleted.
- Status: **done** (2026-08). What landed, and facts worth knowing:
  - New `TableClassProperties` plugin in `src/lib/tableproperties.ts` (commands + conversion + balloon UI) and `src/lib/tablepropertiesview.ts` (the form). Registers the `tableProperties` toolbar component, so the preset contentToolbars work unchanged. Classes live in a `class` attribute on the model table like the 35.4 fork; commands: `tableHeaders`, `tableHeaderColors`, `tableBorder`, `tableAltBGColor`, and `tableWidthClass` — renamed because stock TablePropertiesEditing already registers an inline-style `tableWidth`.
  - Stock `TableProperties` was split: **TablePropertiesEditing stays** (inline-style round-trip + the defaultProperties gotcha from chunk 3 still applies), stock TablePropertiesUI is simply not loaded — our balloon takes its place under the same component name.
  - The `Tablecellproperties/` fork was **not ported after all**: diffing against stock showed its only delta was `disableBorder/Background/Dimensions/Alignment` row-hiding config, which no host uses (dosgato-txstate-admin passes only `configType`/`templateProperties`). Stock `TableCellProperties` (already in the build since chunk 3) covers it; chunk 4's "port" verdict for that directory is amended to "delete".
  - Upcast rules replicate 35.4's empirical output: a wrapping `figure.table`'s classes win over the `<table>` element's own; only bare tables map `border="1"` into the `border` class (and only when they have a class attribute). Classes downcast onto the figure via attributeToAttribute (the mapped view element for a model table is the figure).
  - The legacy `border` attribute round-trips verbatim via a `htmlBorder` model attribute with a custom downcast onto the inner `<table>`. Without this, stock TablePropertiesEditing consumes `border="1"` into tableBorderWidth alone, which re-emits as `border-width:1px` with no border-style — silently dropping the rendered border on Word-paste tables whose only border signal was the attribute (35.4/GHS kept it raw).
  - Legacy `border`/`cellpadding` are also claimed (consumed at highest priority) before stock Table(Cell)PropertiesEditing sees them (2026-09). Otherwise 48 upcasts them into inline `border-width`/`padding` on the table and every cell, and inline styles beat site CSS where the attributes lost to it. On dosgato-txstate the themes own cell padding (normalize reset + `richEditorTable` mixin's `0.5rem 1rem`) and cell borders (the `border` class), so this changed live rendering: Word pastes with `class="border"` + `border="0"` (samples 22, 23, 27) lost their cell borders, and any `cellpadding` replaced the theme padding. `border` still round-trips via htmlBorder; `cellpadding` is dropped (it never affected the live sites). Harness: 35 identical (was 32), 0 inline border/padding gained on tables.
  - 48 gotchas hit: (a) `table.tableCellProperties.scopedHeaders` (default on) derives `headingRows`/`headingColumns` from per-cell `tableCellType` attributes via a post-fixer — a bare `headingRows` write on a table of plain `td`s is instantly reverted; go through `TableUtils.setHeadingRowsCount/setHeadingColumnsCount`. (b) The `_`-prefixed table internals (`_getBalloonTablePositionData`, `_getTableWidgetAncestor`, overlap-split utils, …) are re-exported from `ckeditor5` and work at runtime; the balloon UI uses them rather than vendoring. (c) The table widget toolbar shares the ContextualBalloon — opening the form programmatically before the toolbar shows makes them stack; the real click flow (toolbar first) is unaffected.
  - Form-fill semantics kept from the fork (amended 2026-10, see below): the first option of each dropdown is the implicit default and is never written to content (a classless table reads as "100%/None/first color"); Cancel undoes everything done while the form was open via a per-open batch.
  - Harness: 112/112, 0 failed; `test/exemptions.json` is down to sample 39 only. Formerly-exempt samples 4–38 now round-trip their class sets exactly. New reviewed diffs: sample 6 gains `table-style-align-left` (35.4 dropped it, we preserve it), sample 12 gains a `<thead>` (48 recognizes an all-`<th>` first row as a heading row; renders identically). UI verified headless (playwright): balloon opens from the component, dropdown/toggle changes write classes and heading attrs, reopen reflects state, Cancel reverts, width group stays exclusive, UI output round-trips through setData.
  - Table UI revisited (2026-10, decided with the maintainer): classes over inline styles everywhere an editor makes a choice. (a) Our Headers dropdown and TableHeadersCommand are gone; stock row/column dropdowns' header toggles are the only header control. (b) The balloon gains alignment (center / wrap left / wrap right) bound to stock `tableAlignment`, which already writes `table-style-align-*` classes (block-align values deliberately not offered). (c) Cell properties is stock TableCellPropertiesUI trimmed by CSS to background color and text alignment (`tablecellproperties.ts`; alignment brought back after first being cut; stock builds its view privately, so the subclass only hooks `_showView`), `colorPicker: false` so it's palette-only. (d) `editor.css` previews the classes in the editing view after the `richEditorTable` mixin — stock content CSS drew every table identically, so the toggles looked dead; header colors preview only when hosts pass `color` per option. (e) Form fill now guards with an `_isReady` flag like stock: the old "skip the default on initial fill" check let a refill (reopening on another table) write the default width/color class onto untouched tables. The form's default for a classless table is the option marked `default`, not the first (which showed "None" for tables the site renders with the default header color), and picking the default clears the group rather than writing its class; None is just another host-supplied class. (f) An empty top-left cell in a table with both heading rows and columns gets a `dg-table-corner` class in the editing view only (re-applied after each change:data, since cell re-renders drop it) so editor.css can preview it as a plain cell; the actual th→td conversion is a render-time job in dosgato-render, so existing content benefits without a re-save.
